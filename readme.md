# Coffee Bara POS Kiosk

A touchscreen-friendly café POS built with HTML, CSS, and vanilla JavaScript. A small Node.js server serves the interface and saves completed transactions in a local SQLite database.

## Technology

| Layer | Technology |
| --- | --- |
| Interface | HTML5, CSS3, responsive layouts, locally stored Poppins fonts |
| Browser logic | Vanilla JavaScript ES modules, Fetch API, shared in-memory order state |
| Server | Node.js built-in `http`, `fs`, and `path` modules |
| Database | SQLite, accessed through `better-sqlite3` |
| Images | Local PNG assets for products, branding, mascot, and payment options |

No frontend framework, bundler, or separate database server is required.

## Requirements and dependencies

- **Node.js 22 or newer** and **npm**. The locked `better-sqlite3` dependency requires Node.js `>=22`.
- A modern browser, such as Chrome or Edge.
- Write permission to the project's `db` directory, where the database is created.
- Internet access for the initial dependency installation. Normal local operation uses locally stored images and fonts.

The only direct npm dependency is **`better-sqlite3`**, declared as `^13.0.3` and locked to `13.0.3` in `package-lock.json`. npm installs its required dependencies automatically. You do not need to install SQLite separately.

## Setup

1. Copy or clone the entire project, including `public`, `db`, `package.json`, and `package-lock.json`.
2. Open a terminal in the project folder containing `package.json`.
3. Check the installed tools:

   ```powershell
   node --version
   npm --version
   ```

4. Install the locked dependencies:

   ```powershell
   npm ci
   ```

   `node_modules` is generated by installation and is excluded from Git.

## Run the kiosk

From the project folder, run:

```powershell
npm start
```

Open **http://localhost:3000/** in your browser. The application starts on the Welcome screen. Keep the terminal/server running while using the kiosk; press **Ctrl+C** in that terminal to stop it.

Use the Node.js server rather than opening `public/index.html` directly or through Live Server. The interface needs the server's product and transaction API.

To use another port in Windows PowerShell:

```powershell
$env:PORT = '3001'
npm start
```

Then open **http://localhost:3001/**. To restore the default in that terminal after stopping the server:

```powershell
Remove-Item Env:PORT
```

After changing server/database JavaScript, stop and restart the server. After interface or image changes, refresh the browser; use **Ctrl+F5** if old content is cached.

## Ordering flow

**Welcome → Start Order → Item Selection → Order Summary → Payment Method → Payment → Payment Successful → Receipt → New Transaction → Welcome**

- Categories and search filter the same existing product list.
- Add to Order and quantity controls update the cart and totals.
- Cash payment checks the entered amount and calculates change.
- QR and card payments are **simulations**. Card processing includes a short simulated delay; neither method connects to a payment gateway or charges a real account.
- Successful payments save the transaction and its item details.
- New Transaction clears the current cart, payment state, receipt, displayed totals, search, and category selection. It does **not** delete saved sales.

## Data storage

### Persistent data: SQLite

The database is stored at **`db/cafe.db`**. This filename remains unchanged despite the Coffee Bara rebrand. On server startup, `db/database.js` creates the database and tables if they do not exist.

| Table | Stored information |
| --- | --- |
| `products` | Product ID, name, price, legacy icon, and category |
| `transactions` | Unique reference, payment method, total, amount paid, change, status, and creation time |
| `transaction_items` | Transaction/product links, product-name and unit-price snapshots, quantities, and subtotals |

Prices are in Philippine pesos. The server looks up stored product prices and recalculates transaction totals. A sale and its item records are saved together in a database transaction.

Transaction references retain their existing **`CAFE-...`** format. Creation times use the server machine's local time.

`db/menu.js` defines the starter menu. Startup inserts missing products, normalizes category values, and updates categories for matching product names. It preserves existing products and sales. **Changing a price in `db/menu.js` does not automatically update the price of an existing database product**; existing prices must be updated in the SQLite database separately.

The database and its companion files are excluded from Git by `db/cafe.db*`. A fresh checkout creates a fresh database unless an existing database is copied into `db`.

### Temporary data: browser memory

`public/js/state.js` holds the current products, cart, payment method, and receipt in memory. The app does not save an unfinished cart to local storage. Refreshing or closing the page loses the unfinished order; completed transactions remain in SQLite.

### Local assets

- `public/assets/images/products/`: menu photographs.
- `public/assets/images/payments/`: Cash, QR Payment, and Card Payment images.
- `public/assets/images/`: active Coffee Bara logo and mascot assets, plus the welcome hero image.
- `public/assets/fonts/`: Poppins font files and their license.

Once dependencies are installed, the local kiosk can run without internet access. Simulated payments still require the local Node.js server to save transactions.

### Back up your data

Stop the server before copying `db/cafe.db` to a backup location. Restore it with the server stopped. Preserve the database when moving the kiosk to another computer if you want to keep its sales history. Deleting it loses stored products and transactions; the next startup creates a new database from the starter menu.

## API

| Route | Purpose |
| --- | --- |
| `GET /api/products` | Returns the stored menu products |
| `POST /api/transactions` | Validates and saves a transaction; returns receipt data |

The transaction request supplies `method` (`cash`, `qr`, or `card`), `paid`, and `items` containing product IDs and quantities. The server determines prices from the database.

## Troubleshooting

- **Cannot reach the server:** check that `npm start` is running and that you opened the correct localhost address.
- **Port already in use / `EADDRINUSE`:** stop the previous kiosk server or use the alternate-port instructions above.
- **Missing CSS, JavaScript, or images:** open the Node.js server address, keep the full `public/assets` folder, and refresh with Ctrl+F5.
- **`better-sqlite3` installation or native-module errors:** confirm Node.js is version 22 or newer and rerun `npm ci` on the target machine instead of copying `node_modules` from another computer. If installation reports missing native build tools, follow that error's platform-specific requirements.
- **Database cannot be opened:** confirm the `db` directory exists and is writable.
- **Menu edits do not appear:** restart the server; for existing product prices, check the stored SQLite values as explained above.
